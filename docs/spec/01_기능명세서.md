## 1. 서비스 규칙 요약

1. 습득자는 가입하지 않는다. 사진을 찍고 보관 위치만 고른다.
2. AI는 사진에서 **물건**(종류, 색, 브랜드, 특징)만 판단한다. **건물**은 사진의 위치 정보(EXIF GPS) → 업로드 순간의 브라우저 위치 순으로 추천하고 습득자가 한 번 탭해서 고친다. 좌표는 브라우저 안에서 건물로만 바꾸고 서버로 보내지 않는다. 업로드 전 사진의 위치 정보는 지운다. (10/12, QA B14)
3. 습득물 사진과 세부 특징은 공개하지 않는다. 누구나 볼 수 있는 건 종류, 습득 날짜, 건물뿐이다.
4. 분실자는 학교 이메일 인증으로 가입한다. 이름, 학번은 받지 않는다.
5. 분실자의 설명이 기준 이상 맞을 때만 사진과 보관 위치를 보여준다.
6. 위치를 열어 본 계정과 수령한 계정을 기록해, 물건을 찾아간 사람을 특정할 수 있게 한다.

## 2. 사용자

| 구분 | 설명 | 가입 |
| --- | --- | --- |
| 습득자 | 물건을 주워 사진으로 등록한다 | 하지 않음 |
| 분실자 | 신고하고 일치 판정을 받아 물건을 찾는다 | 학교 이메일(@skuniv.ac.kr) 인증 |
| 관리자 | 종합서비스센터·경비실. 맡겨진 물건의 수령을 처리한다 | 관리자 계정(직접 발급) |
| 체험 사용자 | 심사위원용. 학교 이메일 없이 분실자 흐름을 체험한다 | 체험 로그인 버튼 |

## 3. 용어

- **공개 정보**: 종류(대분류), 습득 날짜, 건물. 로그인한 분실자 누구나 후보 목록에서 본다.
- **비공개 정보**: 사진, 색상, 브랜드, 세부 특징, 보관 위치. 일치 판정을 통과한 분실자만 본다.
- **보관 위치**: 물건이 지금 있는 곳. `그 자리에 둠`(`IN_PLACE`) 또는 `보관처에 맡김`(`HANDED_OVER`) 두 가지뿐이다. 습득자가 가입하지 않아 연락할 방법이 없으므로 "습득자가 보관"은 두지 않는다.
- **보관처**: 물건을 맡길 수 있는 장소. 종합서비스센터, 각 건물 경비실 등. 관리자 계정은 보관처 하나에 속하고 자기 보관처의 물건만 수령 처리한다.
- **습득물 상태**: `분석 중` → `등록됨` → `열람됨` → `수령 완료` / `기한 만료`. AI 분석에 실패하면 `검토 대기`.

## 5. 기능 상세

### F-01 습득물 등록 · P0
- **입력**: 사진 1장(필수), 주운 건물(`그 자리에 둠`이면 필수, `보관처에 맡김`이면 선택), 층(선택), 자세한 위치 설명(선택, 200자), 보관 위치(`그 자리에 둠` / `보관처에 맡김`), 보관처(`보관처에 맡김`일 때 필수)
- **처리**
  1. 사진에 위치 정보(EXIF GPS)가 있으면 그것으로, 없으면 브라우저 위치 권한을 요청해 가장 가까운 건물을 기본값으로 채운다. 계산은 브라우저 안에서 하고(건물 목록의 좌표 사용) 좌표는 서버로 보내지 않는다.
  2. 위치 권한을 거부하거나 300m 안에 건물이 없으면 건물 목록에서 고르게 한다.
  3. `보관처에 맡김`을 고르면 같은 건물의 보관처를 먼저 보여주고, 그 아래 다른 보관처를 보여준다.
  4. 사진을 F-03(블러), F-02(속성 추출)로 넘긴다.
  5. **두 단계 등록**: 사진을 고르면 먼저 분석(`analyze`)해 물건 이름을 보여 주고, 위치·보관 방식을 고른 뒤 확정(`confirm`)한다. 확정 전에는 후보·알림에 나오지 않고, 60분 안에 확정하지 않으면 사진까지 지운다. 한 번에 보내는 등록도 그대로 쓸 수 있다.
  6. `보관처에 맡김`인데 주운 건물을 모르면 비워 둔다. 보관처 건물로 채우지 않는다(매칭의 같은 건물 점수가 틀어지므로). 매칭은 위치를 "모름"으로 본다.
  7. 자세한 위치 설명(예: 3층 엘리베이터 앞 벤치 위)은 판정을 통과한 사람에게만 보이고, 수령·만료 때 다른 비공개 정보와 같이 지운다.
- **출력**: 등록 완료 화면. `보관처에 맡김`이면 보관처의 위치 안내 문구를 보여준다.
- **동의**: 첫 등록 때 동의 화면(사진의 외부 AI 처리 필수, 위치 사용 선택)을 보여 주고 동의 버전을 함께 보낸다. (QA B15)
- **캡차**: Cloudflare Turnstile로 자동 등록·도배를 막는다. (QA W4)
- **고가품**: 보관 방식은 `보관처에 맡김`(센터·경비실)만 고를 수 있다. 두 단계 등록에서는 분석 응답의 `isValuable`이 참이면 등록 화면이 `그 자리에 둠`을 감추고 `보관처에 맡김`을 미리 고른다. 서버도 고가품의 `그 자리에 둠`을 `400 VALUABLE_HAND_OVER_REQUIRED`로 거절한다(한 번에 등록은 AI 분석 뒤 사진을 저장하기 전에 거절). AI가 실패해 종류를 모르면 막지 않고 관리자가 검토한다. (QA B11, open-issues #32)
- **AI 분석 실패**: 등록은 성공으로 처리하고 "분석이 늦어져서 관리자가 확인한 뒤 등록돼요."라고 안내한다. 습득물은 `검토 대기`로 저장된다.
- **예외**
  - 사진에 물건이 없다고 판단되면 다시 찍도록 안내한다.
  - 같은 기기·IP에서 짧은 시간에 과도하게 등록하면 막는다. (초안: 10분에 5건)
  - 사진 용량이 크면 업로드 전에 브라우저에서 줄인다.

### F-02 AI 속성 추출 · P0
- **처리**: 비전 AI가 사진에서 아래를 추출해 저장한다.
  - 공개 속성: `category` (대분류 24개), `subCategory` (세부 종류. 기타 전자기기→마우스·보조배터리, 가방→백팩 등 일부 대분류에만. 화면에는 세부 이름을 보여 주고, 후보 점수에서 세부 종류가 다르면 깎는다)
  - 후보 검색용: `categoryAlt` (2순위 대분류, 없으면 비움). 화면에는 보여주지 않는다.
  - 비공개 속성: `color`(기본 12색, LOST112 색 묶음), `brand`, `features`(정해진 종류의 숨은 특징 최대 4개: 스티커, 흠집, 케이스, 키링, 내용물, 글자, 무늬, 기타), `description`(한국어 설명문)
  - 관리자 목록용 제목(`title`). 비공개 정보가 들어가므로 관리자 화면에만 쓴다.
  - 개인정보 영역(`sensitiveRegions`): 학생증·카드·얼굴이 보이는 위치
  - `description`을 임베딩해 저장한다.
  - 학생증·카드·얼굴 포함 여부(`isSensitive`)를 함께 판단한다.
- **예외**: 실패하면 한 번 재시도하고, 그래도 실패하면 `검토 대기`로 저장해 관리자가 확인한다. AI 응답이 정해진 형식(허용값, 개수)과 다르면 실패로 본다.
- **모델**: Gemini 3.6 Flash, 실패하면 3.5 Flash. 임베딩은 gemini-embedding-001(1536차원).
- **비고**: 응답 형식(JSON 스키마)은 모델 선정 전에 먼저 고정해, 백엔드가 가짜 응답으로 개발을 시작할 수 있게 한다.

### F-03 개인정보 자동 블러 · P0
- **AI로 보내기 전 가리기 (QA B3, 10/27)**: 서버 안의 작은 감지 모델로 얼굴과 글자 영역(카드번호·학번·이름)을 먼저 회색으로 가린다. 외부 AI에는 이 가린 사본만 보내고, 아래 공개본·후보용 블러본도 가린 사본으로 만든다. 가리기에 실패하면 원본을 AI로 보내지 않고 AI 없이 검토 대기로 저장한다.
- **처리**: 사진을 세 가지로 저장한다.
  - 원본: 관리자만 본다. (가리기 전 사진. 관리자가 신분증 주인 확인 등에 쓴다)
  - 공개본(판정 통과 후): 개인정보 영역만 흐린 선명한 사진. 민감한데 영역을 모르면 전체를 흐린다.
  - 후보용 블러본(판정 전 후보 카드): 숨은 특징을 알아볼 수 없을 만큼 강하게 흐린 작은 사진. 민감 여부와 관계없이 항상 흐린다. (10/12 결정, open-issues #29)
- **예외**: 판단이 애매하거나 AI가 실패하면 공개본도 전체를 흐린다.

### F-04 회원가입·로그인 · P0
- **입력**: 학교 이메일, 인증 코드, 비밀번호, 동의(이메일 수집·외부 AI 처리 필수, 위치 선택). 동의 버전과 시각을 저장한다. (QA B15)
- **처리**: 인증 코드를 메일로 보내 확인한 뒤 가입한다. 저장하는 개인정보는 이메일뿐이다.
  - 코드를 확인하면 10분짜리 가입용 토큰을 준다. 이 토큰은 한 번 가입에 쓰면 다시 쓸 수 없다.
- **예외**
  - 학교 도메인이 아니면 가입할 수 없다.
  - 학교 도메인 확인은 소문자로 바꾼 뒤 `@` 뒤 도메인 전체가 허용 목록(환경변수)과 정확히 같은지로 한다. 접미어·포함 비교는 쓰지 않는다.
  - 인증 코드는 6자리, 5분 후 만료, 1회용이다. 5회 틀리면 그 코드는 버리고 다시 받아야 한다. (QA B4, 10/12 확정)
  - 코드 발송 제한: 같은 이메일은 1분에 한 번·하루 10번, 같은 IP는 10분에 10번·하루 50번, 서비스 전체는 하루 상한(환경변수).
  - 이미 가입된 이메일로 코드를 요청해도 같은 응답을 주고, 코드 대신 로그인 안내 메일을 보낸다. 가입 여부가 드러나지 않게 하기 위해서다.

### F-05 체험 로그인 · P0
- **처리**
  1. "체험해 보기"를 누를 때마다 체험 계정(`DEMO`)을 새로 만들어 로그인시킨다. 시도 횟수가 사람마다 따로 계산된다.
  2. 체험 계정은 만든 지 24시간이 지나면 하루 한 번 배치로 삭제한다. 체험 계정이 만든 신고·시도·열람·수령 기록도 함께 지운다.
  3. 체험 계정의 후보 목록에는 시드 습득물만 나오고, 일반 계정의 후보 목록에는 시드 습득물이 나오지 않는다. (초안)
  4. 체험 계정의 판정·열람·수령은 기록은 남기되 **시드 습득물의 상태를 바꾸지 않는다.** 다음 심사위원도 같은 시드로 처음부터 체험할 수 있다.
  5. 체험 계정이 `보관처에 맡김` 물건의 수령 QR을 받으면, 관리자 스캔 없이 "시연: 보관처에서 수령 처리됨" 화면으로 바로 완료한다.
  6. 체험 계정의 열람은 여러 계정 통과 알림(F-10)과 통계(F-15)에서 뺀다.
- **제한**: 같은 IP에서 체험 계정을 과도하게 만들면 막는다. (초안: 10분에 5개)
- **동의·캡차**: 체험 로그인도 외부 AI 처리 동의와 캡차를 거친다.
- **이유**: 심사위원은 학교 이메일이 없어 일반 가입으로는 분실자 흐름을 볼 수 없다. 계정을 하나만 같이 쓰면 시도 횟수가 공유되어 잠기고, 수령까지 하면 시드가 사라진다.
- **표시**: 체험 모드와 시드 데이터에는 "시연용 데이터" 표시를 붙인다.

### F-06 분실 신고 · P0
- **입력**: 종류, 잃어버린 날짜와 시간대, 건물(선택, 모르면 비움), 자유 설명
- **처리**: 설명을 F-02와 같은 속성 체계로 추출하고 임베딩한다.
- **수정**: 신고 후에도 설명을 고칠 수 있다. 고치면 다시 추출·임베딩하고 후보를 다시 고른다.
- **예외**: 설명 추출에 실패하면 신고를 저장하지 않고 다시 시도하도록 안내한다.
- **안내 문구**: "다른 사람은 모를 특징(스티커, 흠집, 안에 든 것)을 적어주세요. 이 특징이 맞아야 물건 위치를 볼 수 있어요."
- **출력**: 신고 직후 F-07 후보 목록으로 이동한다.

### F-07 후보 조회 · P0
- **처리** (회의)
  1. **후보 범위**: 분실 시작 시각 이후에 등록된 `등록됨`·`열람됨` 습득물 중, 습득물의 1순위·2순위 종류(`category`, `categoryAlt`) 중 하나가 신고 종류의 **연관 종류 묶음**에 들어가는 것.
     - 연관 종류 묶음: 지갑↔카드·신분증·현금, 노트북↔태블릿, 휴대폰·이어폰·스마트워치·노트북·태블릿↔충전기, 스마트워치↔시계·액세서리, 가방↔의류↔모자, 교재↔필기구, 지갑↔파우치(가방 중 세부 종류가 파우치인 것만 — 동전지갑이 파우치로 분류되는 경우, 10/30 실제 사진 평가). `기타`는 모든 종류와 묶인다. 종류 24개와 전체 묶음은 02_ERD.md 5장.
  2. **고르기**: 범위 안에서 점수(텍스트 유사도, 속성 일치, 장소 근접도, 시간 근접도)로 **상위 5개**만 고른다. 정확히 같은 종류가 연관 종류보다 높은 점수를 받는다. 같은 건물 우선은 장소 근접도로 반영한다.
  3. **보여주기**: 고른 5개를 **습득 날짜 최신순**으로 보여준다. 점수 순서가 화면에 드러나지 않게 하기 위해서다.
- **출력**: 공개 정보(종류, 습득 날짜, 건물, 층), 남은 시도 횟수, 숨은 특징을 알아볼 수 없을 만큼 강하게 흐린 사진(10/12 결정)을 보여준다. **색과 점수는 보여주지 않는다.**
- **근거 표시**: "같은 종류", "같은 건물", "잃어버린 뒤 2시간 안에 습득"처럼 공개 정보로만 만든 근거를 붙인다. 색·특징 같은 비공개 정보는 근거에 쓰지 않는다. (open-issues #28)
- **제한**: 일치 판정(F-08)은 이 신고의 후보로 보이는(또는 보여 준 적 있고 지금도 후보 범위 안인) 습득물에만 할 수 있다. 새 습득물 때문에 보던 물건이 상위 3개에서 밀려나도 판정할 수 있게 하면서, 습득물 ID를 바꿔 가며 아무 물건이나 시도하는 걸 막는다.
- **예외**: 후보가 없으면 "새 습득물이 등록되면 알려드릴게요"라고 안내하고 신고를 유지한다. (F-13)

### F-08 일치 판정 · P0
- **동작**: 분실자가 후보 하나를 골라 "내 물건인지 확인"을 누른다.
- **특징 대조** (회의): 신고 설명에서 뽑은 특징·속성을 습득물의 비공개 정보와 하나씩 비교해 세 가지로 나눈다.
  - **일치**: 값까지 맞다. 예: 신고 "곰돌이 스티커" ↔ 저장 "곰돌이 스티커"
  - **모순**: 같은 종류의 특징인데 값이 다르다. 예: 신고 "토끼 스티커" ↔ 저장 "곰돌이 스티커"
  - **확인 불가**: 종류만 적었거나("스티커") 저장된 정보에 없는 특징이다. 점수 0.
  - **색·브랜드**는 모순 판정에만 쓰고 일치 개수에는 넣지 않는다. 종류·색·장소만 맞는 경우는 통과시키지 않기 위해서다. 색은 기본 12색 키로 비교하고, 이웃 색(흰색↔회색, 빨강↔분홍, 베이지처럼 노랑↔갈색, 코랄처럼 주황↔분홍, 남색처럼 파랑↔검정 등)과 `기타`는 모순이 아니라 확인 불가로 본다. 브랜드는 영문 머리글자(MICHAEL KORS ↔ MK)도 같은 브랜드로 본다.
- **판정 기준** (회의)
  - **통과**: 특징 일치 1개 이상, 모순 0개
  - **경계**: 특징 일치 1개 이상, 모순 1개 이상 → F-09 확인 질문
  - **실패**: 특징 일치 0개
  - 특징을 잔뜩 나열해도 값이 없으면 전부 확인 불가라 통과하지 못하고, 아무 값이나 적으면 모순이 쌓인다.
- **점수**: 후보 고르기(F-07)에만 쓴다. 판정은 위 기준으로 한다. 결과 화면에는 점수를 보여주지 않는다.
- **결과 표시**: 통과했을 때만 맞은 항목을 보여준다. **실패 응답에는 어떤 항목이 맞았는지 힌트를 주지 않는다.** 힌트가 있으면 설명을 고쳐 가며 정답을 찾아낼 수 있기 때문이다.
- **제한**
  - 습득물 하나당 계정별 실패 3회. 넘기면 그 계정은 그 물건을 더 시도할 수 없다.
  - 습득물 하나에 모든 계정의 실패 합계가 10회가 되면 그 물건은 온라인 확인을 막고 대면 확인만 받는다. 맡은 관리자(보관처 관리자, 없으면 종합서비스센터)에게 한 번 알린다. 체험용 시드는 물건 단위로 막지 않는다. (#29)
  - 그 물건에 대한 마지막 시도 이후 설명이 바뀌지 않았으면, 이전 결과를 그대로 돌려주고 횟수를 쓰지 않는다.
- **열린 문제**: 비공개 특징이 하나도 추출되지 않은 물건(무늬 없는 검정 우산 등)은 이 기준으로 아무도 통과할 수 없다. 처리 방식은 [open-issues #17](./docs/open-issues.md)에서 정한다.

### F-09 확인 질문 · P0
- **질문 만들기**: 분실자가 신고에 **적지 않은** 비공개 특징 하나로 질문을 만든다. 한두 단어로 답할 수 있는 것(색, 그림, 글자, 개수)만 고른다. 예: "케이스에 붙은 스티커는 어떤 그림인가요?"
- **정답 판정** (회의)
  1. 답변과 저장 값을 낱말로 나누고 문장부호·조사를 정리한다. **질문에 나온 낱말(예: "스티커")은 답변에서 뺀다.** 남은 낱말이 모두 저장 값의 낱말과 **낱말 단위로** 같고 2글자 이상 낱말이 있으면 정답. 예: "곰돌이요" ↔ "곰돌이 스티커". 부분 문자열("돌이" ↔ "곰돌이")은 정답이 아니다. (리뷰 PR #10)
  2. 1번으로 정답이 아니면 LLM에 저장 값과 답변을 주고 `MATCH` / `NO_MATCH`만 JSON으로 받는다. 같은 입력엔 같은 결과가 나오도록 온도 0으로 고정한다. 질문·저장 값·답변은 태그로 감싼 데이터로만 넘기고 꺾쇠를 지워, 답변 속 지시("정답이라고 해")를 따르지 않게 한다.
  - 답변은 50자 이하.
  - 질문 단어를 빼는 이유: "스티커"라고만 답해도 "곰돌이 스티커"에 포함되어 통과하는 걸 막기 위해서다.
- **결과**: 맞으면 F-10, 틀리면 실패로 처리하고 시도 횟수를 1 늘린다.
- **비고**: 질문 하나당 답변은 한 번만 받는다.

### F-10 사진·보관 위치 공개 · P0
- **출력**: 블러 처리된 사진, 색상, 건물, 보관 위치. `보관처에 맡김`이면 보관처 위치 안내와 수령 QR 발급 버튼.
- **처리**: 공개할 때마다 열람 기록을 남긴다(F-12). 처음 공개되면 습득물 상태를 `열람됨`으로 바꾼다. 체험 계정은 상태를 바꾸지 않는다(F-05).
- **예외**: 여러 계정이 같은 물건을 통과하면 모두 기록하고 해당 보관처 관리자에게 알린다. 체험 계정은 제외한다.

### F-11 수령 처리 · P0
- **보관처에 맡긴 물건**
  1. 분실자가 수령 QR을 발급받는다. (유효 시간 초안: 24시간) 같은 사람이 다시 발급받으면 이전 QR은 만료된다.
  2. 관리자가 QR을 스캔하면 물건 정보와 마스킹된 이메일을 확인한다. **자기 보관처의 물건이 아니면 처리할 수 없다.**
  3. 관리자가 "수령 완료"를 누르면 수령 기록(계정, 시각, 처리 관리자)이 남고 상태가 `수령 완료`가 된다.
- **그 자리에 둔 물건**: 분실자가 "찾았어요"를 눌러 직접 완료한다. 본인 신고 기록으로 남는다.
- **대면 확인으로 넘어간 물건** (F-08 물건별 실패 10회, #29): 관리자가 찾으러 온 사람의 신분과 물건 설명을 직접 확인하고 "대면 확인 후 수령 완료"를 누른다. 처리 관리자, 시각, 신분 확인 메모(200자, 신분증 번호 전체는 적지 않음)가 남는다. 계정은 모를 수 있어 남기지 않는다. 다른 사람이 받아 둔 QR은 만료된다. 관리 범위 안의 물건만 처리한다(경비실은 자기 보관처, 종합서비스센터는 전체).
- **동시 수령**: 여러 사람이 QR을 갖고 있을 수 있다. 먼저 완료된 쪽만 인정하고, 나머지는 "이미 수령된 물건"으로 안내한다. 물건당 완료된 수령은 1건뿐이다.
- **체험 계정**: F-05 5번대로 관리자 스캔 없이 완료 화면을 보여주고, 시드 상태는 바꾸지 않는다.

### F-12 열람·수령 기록 · P0
- **기록 대상**: 일치 시도(점수, 결과), 위치 열람(계정, 시각), 수령(계정, 방식, 시각, 처리 관리자, 대면 확인이면 신분 확인 메모)
- **보관** (10/12 확정, QA B13, open-issues #26·#33)
  - 수령이 끝나면 사진(원본·공개본·후보용 블러본)과 비공개 정보(색·브랜드·특징·설명·제목)·임베딩을 **바로** 지운다. 종류·건물·날짜·상태는 통계를 위해 남긴다.
  - 수령되지 않은 물건은 등록 30일 뒤 `기한 만료`로 바꾸고 같은 방식으로 지운다. 실물은 보관처가 따로 관리한다. 시드는 제외.
  - 확인 시도·열람·수령(찾아간 사람, 대면 확인 메모 포함) 기록은 수령 또는 만료 30일 뒤 지운다.
  - 체험 수령은 시드를 지우지 않는다.
- **목적 표시**: 개인정보 안내에 "물건을 확인하고 가져간 계정을 특정하기 위해 저장하며, 수령 후 30일 뒤 삭제"를 명시한다.

### F-13 앱 내 알림 · P0
- **처리**: 새 습득물이 `등록됨`이 되면 열려 있는 신고 중 종류와 시간 조건이 맞는 분실자에게 알림을 만든다.
- **내용**: 공개 정보만 담는다. 예: "혜인관에서 이어폰이 새로 등록됐어요."

### F-14 관리자 기본 화면 · P0
- 관리자 로그인, 수령 QR 스캔과 수령 완료 처리(자기 보관처만), `검토 대기` 습득물 확인과 속성 수정, 원본 사진 보기
- `검토 대기` 확인과 `그 자리에 둠` 물건처럼 보관처가 없는 물건을 누가 맡는지는 [open-issues #18](./docs/open-issues.md)에서 정한다.

### F-15 분실 다발 카드 · P0 (마지막 순서)
- 건물·시간대·종류별 등록 건수를 집계해 분실이 몰리는 구간을 카드 하나로 보여준다.
- 시드 데이터 기반이면 화면에 "시드 집계"라고 표시한다.
- **이유**: 공모전 주제가 탐지·예측이라 이 기능이 비어 있으면 주제 적합성에서 깎인다.

### F-16 ~ F-20 (P1, P2)
- **F-16 관리자 목록·일괄 등록**: 센터 습득물 일괄 등록, 전체 목록·검색
- **F-17 미수령 위험 표시**: 귀중품인데 관련 신고가 없거나 보관 기한이 임박한 물건 표시
- **F-18 보관 기한 관리**: 등록 후 30일이 지나면 `기한 만료`로 바꾸는 것과 사진·비공개 정보 삭제는 F-12와 함께 구현됨(10/12). 관리자 알림은 P1
- **F-19 비슷한 사진으로 찾기**: 분실자가 비슷한 물건 사진으로 신고. 사진끼리 비교하는 기능이 추가로 필요해 P1
- **F-20 웹 푸시 알림**: 아이폰은 홈 화면에 추가한 경우에만 동작해 P2
