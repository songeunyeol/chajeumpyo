# 서비스 흐름도

> 2026-10-12 기준. [기능 명세서](../01_기능명세서.md)와 P0 백엔드 구현(PR #2~#20)을 바탕으로 정리했다. 명세가 바뀌면 이 문서도 같이 고친다.
> 아직 정하지 않은 정책은 [open-issues](./open-issues.md) 번호로 표시했다.

## 0. 한 줄 요약

```
습득자: 사진 찍기 ─▶ AI가 물건 정보를 읽고 숨겨서 저장
분실자: 특징 설명 ─▶ 후보 5개 ─▶ 일치 판정 ─▶ 통과하면 사진·위치 공개 ─▶ 수령
관리자: 맡겨진 물건의 QR 수령 처리, 검토 대기 확인, 분실 다발 카드
```

핵심 원칙: **주운 물건의 세부 정보는 숨기고, 주인이 맞혀야만 보여준다.**

| 사용자 | 가입 | 주요 기능 |
| --- | --- | --- |
| 습득자 | 하지 않음 | F-01 등록 |
| 분실자 | 학교 이메일 인증 | F-04, F-06~F-11, F-13 |
| 체험 사용자 | 체험 로그인 버튼 | F-05 (분실자 흐름 전체) |
| 관리자 | 직접 발급 | F-11 수령 처리, F-14, F-15 |
| 시스템 | - | F-02 추출, F-03 블러, F-12 기록 삭제, 체험 계정 정리 |

## 1. 습득자 흐름 (로그인 없음)

```
[사진 촬영] ─▶ [건물 선택] ─▶ [보관 위치 선택] ─▶ [등록]
                  │                 │
     위치 권한 → 가장 가까운 건물    ├─ 그 자리에 둠 (IN_PLACE)
     거부 → 목록에서 고름           └─ 보관처에 맡김 (HANDED_OVER) → 보관처 선택 (같은 건물이 위)
```

등록 후 서버 처리 (`POST /found-items`):

```
사진 ─▶ EXIF·GPS 제거 ─▶ AI 속성 추출 (실패 시 1번 재시도)
                          │
           ┌──────────────┼────────────────────┐
         성공           물건 없음            계속 실패
           │              │                    │
   종류 (공개)           422                 검토 대기로 저장
   2순위 종류 (검색용)   "다시 찍어 주세요"    201 + status REVIEW
   색·브랜드·특징·설명                       "관리자가 확인한 뒤 등록돼요"
   (비공개)
   민감 여부 → 민감하면 전체 블러본, 아니면 1024px 축소본 (#11)
   설명 임베딩 저장
           │
     상태: 등록됨 ─▶ 조건이 맞는 열린 신고의 분실자에게 알림 생성 (F-13)
```

- 같은 기기·IP는 10분에 5건까지 등록할 수 있다. (초안)
- 사진 파일의 위치 정보는 쓰지 않는다. 건물은 브라우저 위치로 추천한다.

## 2. 분실자 흐름

### 2-1. 가입·로그인 (F-04, F-05)

```
일반: 학교 이메일 ─▶ 인증 코드 (10분, 5회) ─▶ 가입용 토큰 (10분, 1회용) ─▶ 비밀번호 ─▶ 로그인 (7일 토큰, #14)
체험: [체험해 보기] ─▶ 누를 때마다 새 DEMO 계정 (24시간 뒤 삭제) ─▶ 바로 로그인
```

### 2-2. 신고 → 후보 (F-06, F-07)

```
[분실 신고] 종류, 날짜·시간대, 건물 (선택), 자유 설명
      │
  설명에서 AI가 특징 추출 + 임베딩 (실패하면 저장하지 않고 502, 다시 시도 안내)
      │
[후보 고르기]
  범위: 분실 시각 이후 등록 + 상태(등록됨·열람됨) + 종류가 연관 묶음에 해당 (#10)
        예: 이어폰 신고 → 이어폰·충전기 습득물까지
  점수: 텍스트 유사도 0.4 + 속성 일치 0.3 + 장소 근접 0.2 + 시간 근접 0.1
  상위 5개 선택 ─▶ 화면에는 습득 날짜 최신순으로 표시 (점수 순서를 숨기기 위해, #6)
      │
[후보 목록] 종류, 습득일, 건물, 남은 시도 횟수만 보임. 사진·색·점수는 없음
  후보가 없으면 "새 습득물이 등록되면 알려드릴게요" → 나중에 알림
```

신고 설명은 나중에 고칠 수 있고, 고치면 다시 추출해서 후보를 다시 고른다. (#8)

### 2-3. 일치 판정 (F-08, F-09) — 서비스의 핵심

```
[내 물건인지 확인] ── 지금 이 신고의 후보인 물건만 가능 (아니면 403)
      │
  설명이 지난번 시도와 같으면 ─▶ 이전 결과를 그대로 반환, 횟수 차감 없음
      │
  특징을 하나씩 대조 (#7)
    일치: 값까지 맞음 ("곰돌이 스티커" ↔ "곰돌이 스티커")
    모순: 같은 종류의 특징인데 값이 다름 ("토끼 스티커" ↔ "곰돌이 스티커")
    확인 불가: 종류만 적었거나 저장된 정보에 없음
    색·브랜드는 모순 판정에만 사용. 비슷한 색은 확인 불가
      │
  ┌───────────────┬──────────────────────────┬──────────────────────┐
 통과             경계                        실패
 일치≥1, 모순 0   일치≥1, 모순≥1               일치 0
  │               │                            │
 공개            확인 질문                     실패 1회 (힌트 없음)
                  신고에 안 적은 특징 1개로     3회 실패하면 그 물건은 잠김
                  답은 1번만                   
                  │
            맞음 → 공개 / 틀림 → 실패 1회
            물어볼 특징이 없으면 → 실패 (#25)
```

- 확인 질문 정답 판정: 질문에 나온 단어를 빼고 2글자 이상 포함 비교, 아니면 LLM이 MATCH/NO_MATCH로 판정한다. (#9)
- 비공개 특징이 하나도 없는 물건은 지금 기준으로 누구도 통과할 수 없다. (#17, 결정 필요)
- 같은 사람이 같은 물건에 동시에 요청해도 한 번만 처리되도록 잠금을 건다.

### 2-4. 공개 → 수령 (F-10, F-11, F-12)

```
[사진·위치 공개] 블러본 사진, 색, 건물, 보관 위치
  열람 기록 저장, 처음 공개되면 상태가 열람됨으로 바뀜
  여러 계정이 통과하면 해당 보관처 관리자에게 알림 (#13)
      │
  ┌───────────────────────────┬──────────────────────────────┐
 보관처에 맡김                  그 자리에 둠
  │                             │
 수령 QR 발급 (24시간)          [찾았어요] ─▶ 본인이 직접 완료
 재발급하면 이전 QR 만료
  │
 관리자가 스캔 ─▶ [수령 완료]
      │
  물건당 완료된 수령은 1건뿐. 늦게 온 쪽은 "이미 수령된 물건" (409)
  상태: 수령 완료 ─▶ 30일 뒤 시도·열람 기록 삭제 (수령 기록 보관 기간은 #26)
```

## 3. 관리자 흐름 (같은 앱의 `/admin`)

```
관리자 로그인 (직접 발급한 계정, 보관처 하나에 소속)
  ├─ QR 스캔 ─▶ 물건 정보 + 가려진 이메일 ─▶ 수령 완료 (자기 보관처 물건만)
  ├─ 습득물 목록·상세 ─▶ 원본 사진 보기, AI 속성 수정, 검토 대기 승인 → 등록됨
  │     종합서비스센터·보관처 없는 관리자: 전체 / 경비실: 자기 보관처만 (#18)
  ├─ 알림 ─▶ 여러 계정 열람 경고
  └─ 분실 다발 카드 (F-15) ─▶ 건물·시간대·종류별 집계에서 가장 몰린 구간 한 줄
                               예: "청운관에서 오후 1~3시에 이어폰이 가장 많아요"
                               시드 데이터면 "시드 집계" 표시
```

## 4. 체험 모드 (심사위원용, F-05)

```
[체험해 보기] ─▶ 새 DEMO 계정
  후보에는 시드 습득물만 보임 (일반 계정에는 시드가 안 보임)
  판정·열람·수령 기록은 남지만 시드 상태는 바뀌지 않음 → 다음 심사위원도 처음부터 체험 가능
  보관처 물건 수령 시 관리자 스캔 없이 "시연: 보관처에서 수령 처리됨" (pickup.method = DEMO)
  다중 열람 알림과 통계에서 제외
```

## 5. 습득물 상태

```
         (AI 실패)
 분석 중 ─────────▶ 검토 대기 ──(관리자 승인)──┐
    │                                          ▼
    └─────────────────────────────────▶ 등록됨 ──(첫 공개)──▶ 열람됨 ──(수령)──▶ 수령 완료
                                              └────────── 30일 경과 (F-18, P1) ──────▶ 기한 만료
```
