> 2026-10-11 기준 기능 명세서(01)와 구현된 백엔드 API를 바탕으로 작성. 아래 구분선 사이를 그대로 붙여 넣는다.

## 0. 요청

캠퍼스 분실물 웹앱 **"찾음표"**의 반응형 웹 UI를 디자인해 줘. 모바일 우선 PWA이고, 대학 공모전 출품작이야. 실제 서비스처럼 보이는 완성도가 필요해.

결과물:
1. **디자인 토큰**: 색(메인, 배경, 텍스트, 상태색), 글자 크기 단계, 간격, 둥근 정도, 그림자. Tailwind CSS 설정으로 옮길 수 있게 CSS 변수로 정리해 줘.
2. **공통 컴포넌트**: 버튼(주/보조/위험), 입력창, 텍스트 영역, 선택 칩, 셀렉트, 후보 카드, 상태 배지, 알림 항목, 빈 화면, 토스트, 바텀시트, 단계 표시, 로딩 스켈레톤.
3. **아래 4장의 화면 전부**와 화면별 상태 변형(로딩, 빈 화면, 오류). 기준은 360px 폭 모바일이야.
4. PC(1280px)에서 보이는 모습 2~3개. 분실자 화면은 가운데 정렬한 최대 폭 레이아웃, 관리자 화면은 넓은 목록 레이아웃.

구현 조건: 프론트는 **React + Tailwind + shadcn/ui**로 만들 거라 컴포넌트 구조와 이름을 shadcn/ui에 맞춰 줘. 폰트는 **Pretendard**, 아이콘은 **Lucide**만 쓰고 이모지는 쓰지 마.

## 1. 서비스 한 줄 설명

주운 사람은 **사진만 찍어 올리고**, 잃어버린 사람은 **"남들은 모르는 특징"을 설명해서 맞혀야** 사진과 보관 위치를 볼 수 있는 분실물 서비스. AI가 사진에서 물건의 종류·색·브랜드·특징을 읽고, 분실자의 설명과 대조해 본인 물건인지 판정한다.

## 2. 디자인 원칙 (꼭 지켜야 함)

1. **비공개 정보를 함부로 보여주지 않는다.** 판정을 통과하기 전에는 종류, 습득 날짜, 건물만 보인다. 후보 목록에 **사진, 사진 썸네일, 색, 일치도·점수·순위 표시를 넣지 않는다.** 대신 종류 아이콘으로 카드를 구분한다.
2. **실패했을 때 힌트를 주지 않는다.** 판정에 실패하면 어떤 항목이 맞았거나 틀렸는지 보여주지 않는다.
3. **잠긴 것과 열린 것을 분명하게 나눈다.** 판정 전 정보는 자물쇠·흐림 같은 시각 언어로, 통과 후 공개는 확실한 해제 연출로 보여준다.
4. **습득자는 가입하지 않는다.** 등록은 사진 찍기부터 완료까지 3번 안쪽의 탭으로 끝나야 한다.
5. **믿음이 가는 톤.** 학교 공식 서비스처럼 차분하고 깔끔하게. 귀엽기만 한 톤은 피한다. 상태색은 통과(초록 계열), 확인 질문(주황 계열), 실패·잠김(빨강 계열), 검토 대기(회색·노랑 계열)로 구분한다.
6. **시연 표시.** 체험 모드에는 화면 상단에 작은 "체험 모드" 띠를, 시연용 데이터에는 "시연용 데이터" 배지를 붙인다. 심사위원이 보는 화면이라 눈에 띄되 거슬리지 않게.
7. 접근성: 터치 영역 44px 이상, 대비 4.5:1 이상, 색으로만 상태를 구분하지 않는다(아이콘과 글자를 함께 쓴다).

## 3. 데이터 예시 (화면에 그대로 써도 됨)

- 종류: 무선 이어폰, 충전기·보조배터리, 우산, 학생증·카드, 지갑, 텀블러, 필통·필기구, 노트북·태블릿, 옷·가방, 기타
- 건물: 혜인관, 청운관, 북악관, 한림관 (예시)
- 보관처: 종합서비스센터("혜인관 1층 정문 옆"), 청운관 경비실("1층 엘리베이터 맞은편")
- 학교 이메일: `@skuniv.ac.kr`
- 습득물 상태: 분석 중, 등록됨, 열람됨, 수령 완료, 기한 만료, 검토 대기

## 4. 화면 (지금 개발 범위, P0)

### 4-1. 분실자 흐름 (가장 중요, 심사위원이 실제로 체험함)

1. **첫 화면**: 서비스 소개 한두 줄, [로그인], [회원가입], **[체험해 보기]**(심사위원용, 눈에 잘 띄게). 아래에 "물건을 주웠어요" 진입 버튼.
2. **회원가입 3단계**
   - ① 학교 이메일 입력. 학교 도메인이 아니면 오류.
   - ② 인증 코드 6자리 입력. 10분 타이머, 다시 받기, 틀림(남은 횟수), 5회 초과.
   - ③ 비밀번호 설정. 받는 개인정보는 이메일뿐이라는 안내.
3. **로그인**
4. **홈(분실자)**: 내 신고 목록(진행 중/닫힘), [분실 신고하기], 새 알림 표시.
5. **분실 신고 작성**
   - 입력: 종류(칩 선택), 잃어버린 날짜와 시간대, 건물(선택, "잘 모르겠어요" 가능), 자유 설명.
   - 설명 입력창 위 안내: "다른 사람은 모를 특징(스티커, 흠집, 안에 든 것)을 적어주세요. 이 특징이 맞아야 물건 위치를 볼 수 있어요."
   - 상태: AI 분석 중(수 초), 분석 실패("잠시 후 다시 시도해 주세요", 입력은 유지).
6. **후보 목록**: 신고 직후 이동.
   - 카드 최대 3개, 습득 날짜 최신순. 카드에는 **종류 아이콘, 종류, 습득 날짜, 건물, 남은 시도 횟수(예: 3번 중 2번 남음)**만 있다. 사진·색·점수는 없다.
   - 카드 버튼: [내 물건인지 확인]. 잠긴 물건은 비활성 처리하고 "시도 횟수를 모두 썼어요" 표시.
   - 빈 화면: "아직 비슷한 물건이 없어요. 새 습득물이 등록되면 알려드릴게요."
   - 상단에 신고 요약과 [설명 고치기].
7. **신고 상세·설명 고치기**: 설명을 고치면 후보를 다시 고른다는 안내, [신고 닫기].
8. **판정 중**: 몇 초 걸리는 로딩. 불안하지 않게 진행 연출.
9. **판정 결과** (4가지)
   - 통과: "내 물건이 맞아요" + 맞은 특징 목록 → [사진과 위치 보기].
   - 확인 질문으로 이동(경계): "한 가지만 더 확인할게요".
   - 실패: "설명과 일치하지 않아요" + 남은 횟수. **어떤 항목이 틀렸는지는 보여주지 않는다.** 설명을 더 자세히 고쳐 보라고 안내.
   - 잠김: 3번 모두 실패. 보관처에 직접 문의하라는 안내.
   - 참고: 설명을 고치지 않고 다시 확인하면 횟수를 쓰지 않고 이전 결과를 다시 보여준다. 이 사실을 작은 글씨로 안내.
10. **확인 질문**: 질문 1개(예: "케이스에 붙은 스티커는 어떤 그림인가요?"), 짧은 답 입력. **한 번만 답할 수 있다**는 경고. 맞으면 공개, 틀리면 실패 화면.
11. **사진·위치 공개**: 잠금 해제 연출. 흐림 처리된 사진(개인정보가 있으면 사진 전체가 흐림), 색, 건물, 보관 위치.
    - `보관처에 맡김`: 보관처 이름과 위치 안내 + [수령 QR 받기].
    - `그 자리에 둠`: "발견된 자리에 그대로 있어요" + 건물 + [찾았어요].
    - 하단 안내: "물건을 확인한 계정은 기록되며, 수령 후 30일 뒤 삭제돼요."
12. **수령 QR**: 큰 QR, 유효 시간(24시간) 표시, [다시 받기](이전 QR은 만료된다는 안내). 보관처에서 직원에게 보여주라는 안내.
    - 이미 다른 사람이 수령한 경우: "이미 수령된 물건이에요".
13. **수령 완료**: 일반 완료 화면과 체험 모드 전용 "시연: 보관처에서 수령 처리됨" 화면.
14. **알림함**: 항목 예시 "혜인관에서 무선 이어폰이 새로 등록됐어요." 안 읽음 점 표시, [모두 읽음]. 누르면 해당 신고의 후보 목록으로 이동.
15. **내 정보**: 이메일, 로그아웃, 개인정보 안내.

### 4-2. 습득자 흐름 (로그인 없음)

1. **사진 찍기**: 카메라 바로 열기 / 앨범에서 고르기. 촬영 팁("물건 전체가 보이게").
2. **등록 정보**
   - 건물: 위치 권한을 허용하면 가장 가까운 건물이 미리 선택되고 한 번 탭해서 바꿀 수 있다. 권한을 거부하면 건물 목록에서 고른다.
   - 보관 위치 선택 2개: [그 자리에 둠] / [보관처에 맡김].
   - 보관처에 맡김을 고르면 보관처 목록. 같은 건물 보관처가 먼저 나온다.
   - [등록하기].
3. **등록 중**: 사진 업로드와 AI 분석(최대 10초).
4. **등록 완료** (상태별)
   - 정상: "등록됐어요" + AI가 알아본 종류. 보관처에 맡겼다면 보관처 위치 안내.
   - 검토 대기: "분석이 늦어져서 관리자가 확인한 뒤 등록돼요."
   - 물건이 안 보임: "사진에서 물건을 찾지 못했어요. 다시 찍어 주세요."
   - 너무 잦은 등록: "잠시 후 다시 시도해 주세요."
   - 사진 용량 초과.
   - 습득자는 AI 분석 결과를 고치지 않는다.

### 4-3. 관리자 (같은 앱의 /admin, 직원이 휴대폰으로 QR을 스캔하는 상황이 기본)

1. **관리자 로그인**: 분실자 로그인과 구분되는 화면.
2. **관리자 홈**: [QR 스캔] 큰 버튼, 검토 대기 건수, 분실 다발 카드.
3. **습득물 목록**: 상태 필터(검토 대기/등록됨/열람됨/수령 완료), 종류·건물·습득일. 관리자는 원본 사진 썸네일을 볼 수 있다.
4. **습득물 상세**: 원본 사진, AI가 뽑은 속성(종류, 2순위 종류, 색, 브랜드, 특징 태그, 설명) 수정, 보관 위치, 검토 대기 → [확인 완료] 처리, 같은 물건을 여러 계정이 열람했다는 경고 표시.
5. **QR 스캔**: 카메라 화면 → 확인 화면(물건 정보, 가려진 이메일 `ab***@skuniv.ac.kr`) → [수령 완료].
   - 오류 상태: QR 만료, 이미 수령됨, 다른 보관처의 물건이라 처리할 수 없음.
6. **분실 다발 카드**: 카드 하나. 예: "청운관에서 오후 1~3시에 무선 이어폰 분실이 가장 많아요." 건물·시간대·종류별 막대그래프 하나. 시드 데이터일 때 "시드 집계" 배지.
7. **관리자 알림**: 여러 계정이 같은 물건을 열람했을 때 알림.

### 4-4. 공통

- 하단 탭(분실자: 홈, 알림, 내 정보) / 관리자는 별도 내비게이션
- 로딩 스켈레톤, 네트워크 오류, 404, 로그인 만료("다시 로그인해 주세요")
- PWA 앱 아이콘(192px, 512px)과 로고 시안

## 5. 향후 기능 (P1·P2, 화면 구조만 가볍게)

지금 레이아웃이 나중에 아래 기능을 받을 수 있게만 고려해 줘. 시안은 간단해도 된다.

- **F-16 관리자 일괄 등록·검색**: 사진 여러 장을 한 번에 올리는 화면, 목록 검색.
- **F-17 미수령 위험 표시**: 목록에서 "귀중품인데 신고 없음", "보관 기한 임박" 배지.
- **F-18 보관 기한 관리**: 등록 30일 후 기한 만료 상태와 관리자 알림.
- **F-19 비슷한 사진으로 찾기**: 분실 신고에서 비슷한 물건 사진을 올리는 선택 입력.
- **F-20 웹 푸시 알림**: 알림 허용 요청 화면. 아이폰은 홈 화면에 추가해야 한다는 안내.

## 6. 하지 말 것

- 후보 카드에 사진, 색, 일치도 바, 점수, 순위 표시
- 실패 화면에 맞은 항목·틀린 항목 표시
- 확인 질문을 여러 단계로 이어지는 퀴즈처럼 만들기 (질문은 1개, 답은 1번)
- 습득자 가입·로그인 화면, 습득자에게 이름·연락처 받기
- 학번·이름 입력 칸
- 교내 지도, 히트맵 (P0 아님)
- 특정 브랜드(당근, 토스 등) 디자인을 그대로 따라 하기
