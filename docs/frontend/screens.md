# 프론트 화면 목록과 기능 (P0)

> 2026-10-25. 기준: 구현된 백엔드 API(`docs/api/openapi.json`, `03_API명세서.md`), 기능 명세서(01), QA 수락 기준표(`qa/CANONICAL-AC-PACK.md`).
> 디자인·프론트·연결 세 작업이 이 문서를 같은 계약으로 쓴다. 화면 ID(예: `L-05`)로 서로 부른다.
> 옛 디자인 프롬프트(`docs/design/claude-design-prompt.md`)와 다른 점은 이 문서가 우선이다(후보 3개, 흐린 썸네일, 근거, 대면 확인, 동의, 캡차, 24종류).

## 0. 디자인 방향: 시안 11 "창구 띠"

`docs/design/system/ref/row3-chosen-11.png` (팀 보드 "찾음표 첫 화면 23안"의 11번).

- 첫 화면이 세 개의 큰 띠로 나뉜다: **초록 띠 "물건을 주웠어요"(가입 없이 사진만)** / **아이보리 띠 "잃어버렸어요"(로그인·회원가입)** / **베이지 띠 "체험해 보기"(심사위원용)**.
- 고른 이유
  1. 서비스의 입구가 정확히 셋(습득자·분실자·심사위원)이고, 띠 하나가 한 입구라 설명 없이 고를 수 있다. 띠 전체가 터치 영역이라 한 손으로 누르기 쉽다.
  2. 띠 색을 흐름 색으로 이어 쓸 수 있다. 습득자 흐름 = 초록, 분실자 흐름 = 아이보리 바탕에 초록 강조, 체험 = 베이지 띠(상단 "체험 모드" 띠와 같은 색). 화면이 23개로 늘어도 "지금 어느 흐름인지"가 색으로 유지된다.
  3. 짙은 초록 + 따뜻한 미색은 "학교 공식 서비스" 톤(차분·신뢰)에 맞고, 이미 Figma 토큰에 있는 초록(`oklch(0.42 0.1 155)` 계열)과 이어진다. 흰 글자/짙은 초록 대비가 충분하다(4.5:1 이상).
  4. 1번째 줄 시안(01~04)은 흑백·선 위주라 23개 화면으로 늘리면 단조롭고 상태색(통과·확인 질문·실패·잠김)을 얹을 바탕이 약하다. 10(야간 칠판)은 어두워 사진·QR 화면과 안 맞고, 09는 사진 의존, 12는 첫 화면 외에 이어 쓸 구조가 없다.
- 지킬 것: 폰트 Pretendard, 아이콘 Lucide만(이모지 금지), 360px 모바일 기준 + PC는 가운데 최대 폭(분실자) / 넓은 목록(관리자), 터치 44px, 색만으로 상태 구분 금지.

## 1. 화면 목록

ID 규칙: `C` 공통, `F` 습득자(Finder), `L` 분실자(Lost), `A` 관리자(Admin). **P0** = 제출 전 필수.

### 공통

| ID | 화면 | 기능 | API |
|---|---|---|---|
| C-01 | 첫 화면 (창구 띠 3개) | 주웠어요 → F-01, 잃어버렸어요 → L-01(로그인), 체험해 보기 → C-03. 한 줄 소개 "사진은 바로 올리고, 특징이 맞아야 위치가 열린다." 관리자 로그인 링크는 아래 작게 | — |
| C-02 | 동의 화면 (바텀시트) | 한 화면에서 ① 학교 이메일 수집(회원만) ② 위치 사용(선택) ③ 사진 외부 AI 처리. 습득자·체험·가입 각각 처음 한 번. 동의 버전은 `CONSENT_VERSION` | 각 요청 본문의 `consent` |
| C-03 | 체험 시작 | 동의 + 캡차(Turnstile, 개발 중엔 통과 토큰) → 체험 계정 발급 → L-03. 이후 모든 화면 상단에 "체험 모드" 띠 | `POST /auth/demo` |
| C-04 | 알림함 | 목록(안 읽음 점), 한 개 읽음, 모두 읽음, 누르면 해당 신고 후보(L-05) 또는 관리자 상세(A-04) | `GET /notifications`, `PATCH /notifications/:id/read`, `PATCH /notifications/read-all` |
| C-05 | 내 정보 | 이메일(가림), 역할, 로그아웃, 개인정보 안내(수집 항목·30일 삭제) | `GET /me` |
| C-06 | 상태 화면 | 로딩 스켈레톤, 네트워크 오류, 404, 로그인 만료("다시 로그인해 주세요"), 요청 제한(429) | — |
| C-07 | 공용 지도 카드 (B17) | 네이버 지도에 건물 핀. 키가 없거나 인증 실패(`navermap_authFailure`)면 건물 목록으로 대체. 분실물 좌표는 절대 표시하지 않음(건물 좌표만) | `GET /buildings` |

### 습득자 (로그인 없음, 초록)

| ID | 화면 | 기능 | API |
|---|---|---|---|
| F-01 | 사진 찍기 | 카메라 바로 열기 / 앨범. 촬영 팁. HEIC·JPG·PNG·WEBP, 용량 안내 | — |
| F-02 | 등록 정보 | **건물 추천: 사진 EXIF GPS → (위치 동의 시) 브라우저 위치 → 직접 선택** 순, 한 번 탭해 고침. 좌표는 **브라우저 안에서 건물로 바꾼 뒤 버린다(서버로 보내지 않음, B14)**. 층(선택, 지하 음수). 보관: [그 자리에 둠] / [보관처에 맡김] → 보관처 목록(같은 건물 먼저). 캡차. [등록하기] | `GET /buildings`, `GET /storage-places`, `POST /found-items`(multipart) |
| F-03 | 등록 중 | 업로드·AI 분석 진행(최대 10초) | 위 요청 대기 |
| F-04 | 등록 결과 | 상태별: 등록됨(AI가 알아본 종류·제목) / 검토 대기 / 물건이 안 보임(422, 다시 찍기) / 너무 잦음(429) / 용량 초과(413). **고가품인데 그 자리에 둠이면 "가까운 보관처에 맡겨 주세요" 안내(등록 응답의 보관 안내 필드, `packages/shared/src/api/found-items.ts` 참고)** | 응답 |

### 분실자 (회원, 아이보리 + 초록 강조)

| ID | 화면 | 기능 | API |
|---|---|---|---|
| L-01 | 로그인 | 이메일·비밀번호, 회원가입·체험 링크 | `POST /auth/login` |
| L-02 | 회원가입 3단계 | ① 학교 이메일(`@skuniv.ac.kr`만, 다른 도메인 오류) ② 6자리 코드, **5분 타이머**, 다시 받기(대기 시간), 틀림·5회 초과 ③ 비밀번호 + 동의(C-02) | `POST /auth/email/code`, `/auth/email/verify`, `/auth/signup` |
| L-03 | 홈 | 내 신고 목록(진행 중/닫힘), [분실 신고하기], 알림 점, 하단 탭(홈·알림·내 정보) | `GET /lost-reports` |
| L-04 | 분실 신고 작성 | 종류(24개 칩, 검색), 잃어버린 시간 범위, 건물(선택·"모르겠어요"), 설명(숨은 특징 안내 문구). AI 분석 중/실패(입력 유지) | `POST /lost-reports` |
| L-05 | 후보 목록 | **최대 3개**, 습득 날짜 최신순. 카드: 종류 아이콘·종류·습득 날짜·건물·층·**강하게 흐린 썸네일**·**근거 칩(같은 종류/같은 건물/시간 가까움 등 공개 정보만)**·남은 시도(3번 중 n번). 잠김(내 3회 소진) / **대면 확인만(`inPersonOnly`)** 표시. 빈 화면. 상단 신고 요약 + [설명 고치기] | `GET /lost-reports/:id/candidates` |
| L-06 | 신고 상세·설명 고치기 | 설명 수정(후보 다시 고름 안내), [신고 닫기] | `PATCH /lost-reports/:id` |
| L-07 | 판정 중 | 수 초 로딩, 불안하지 않은 진행 연출 | `POST /lost-reports/:id/claims` |
| L-08 | 판정 결과 | 통과 → [사진과 위치 보기] / 확인 질문 → L-09 / 실패(남은 횟수, **어느 항목이 틀렸는지 절대 안 보임**) / 잠김(3회) / **대면 확인으로 넘어감(409 IN_PERSON_REQUIRED, 보관처 방문 안내)**. "설명을 안 고치고 다시 누르면 횟수를 쓰지 않아요" 작은 글씨 | 응답 |
| L-09 | 확인 질문 | 질문 1개, 짧은 답, **한 번만** 경고 | `POST /claims/:attemptId/answer` |
| L-10 | 사진·위치 공개 | 잠금 해제 연출. 공개 사진(민감하면 흐림), 종류·색·건물·층, 보관 방식별: 보관처(이름·안내) + [수령 QR 받기] / 그 자리(건물·층) + [찾았어요]. **고가품 대면 수령 안내(`pickupNotice`)**. "확인한 계정은 기록, 수령 30일 뒤 삭제" | `GET /found-items/:id/detail` |
| L-11 | 수령 QR | 큰 QR(`qrcode.react`), 24시간 만료 표시, 다시 받기(이전 QR 만료 안내), 이미 수령됨 | `POST /found-items/:id/pickup-qr` |
| L-12 | 수령 완료 | 일반 / 체험("시연: 보관처에서 수령 처리됨") / 그 자리 찾았어요 완료 | `POST /found-items/:id/self-pickup` |

## 2. 공통 규칙 (모든 화면)

- 비공개 정보 원칙: 판정 통과 전에는 종류·날짜·건물·층·강한 블러 썸네일·공개 근거만. 색·브랜드·특징·점수·순위 표시 금지.
- 실패 화면에 맞은/틀린 항목 표시 금지. 확인 질문은 1개·1번.
- 상태색: 통과(초록), 확인 질문(주황), 실패·잠김(빨강), 검토 대기(회색·노랑), 대면 확인(남색 등 구분 색). 아이콘+글자 함께.
- 체험 모드 띠, 시드 데이터 배지.
- 폼 검증은 `@chajeumpyo/shared`의 zod 스키마 그대로(react-hook-form + zodResolver). 에러 코드별 문구는 `ERROR_STATUS` 기준.
- 스택(`docs/tech-stack.md`): React + Vite SPA, React Router, TanStack Query, Tailwind + shadcn/ui, vite-plugin-pwa, qrcode.react, react-hook-form + zod. 지도는 네이버 지도(B17).
